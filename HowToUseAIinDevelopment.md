# Do's And Don't In Development
**1. Write first, ask AI second**
- Before opening AI:
- Read the problem.
- Design the solution yourself.
- Write pseudocode.
- Implement at least a rough version.
- Only then ask AI
```
"Review my approach."
"What edge cases am I missing?"
"How can I improve this code?"
```
- **2. Never copy code you don't understand**
- If you can't explain every line, don't paste it into production.
- When AI gives code:
```
Read it line by line.
Rewrite parts yourself.
Add comments explaining why it works.
```
- **3. Use AI for learning, not solving**
- Instead of:
```
❌ "Build authentication for me."
```
- Ask:
```
"Explain the authentication flow."
"Give me hints."
"Review my implementation."
```
- Treat AI like a senior developer who guides you.

- **4. Keep a "No AI" practice time**
- Spend some time every week coding without AI.
- Examples:
```
Solve algorithm problems.
Build small features.
Debug issues manually.
Read documentation directly.
```
- Even 30–60 minutes a few times a week helps maintain your skills.

- **5. Read source code and documentation**
- Many developers today jump directly to AI.
- A stronger habit:
```
Read official docs first.
Search codebases.
Read open-source projects.
```
- For example, if learning a framework from React documentation or Django documentation, try understanding the docs before asking AI.

- **6. Use the "three-attempt rule"**
- Before asking AI:
- Think about the problem.
- Try one solution.
- Try a second or third approach.
- If you're still stuck, then ask.
- This prevents dependency.

- **7. Maintain a personal knowledge base**
- After solving something:
```
Write notes.
Save patterns.
Record mistakes.
Create your own snippets.
```
- The act of writing helps memory much more than reading AI output.

- **8. Turn off AI during debugging sometimes**
- Debugging is one of the most valuable developer skills.
- Instead of immediately asking AI:
```
Read logs.
Use breakpoints.
Trace execution.
```
- You will build intuition that AI cannot replace.

- **9. Ask for explanations, not answers**
- When using AI, prefer prompts like:
```
"Give me a hint."
"What's wrong with my reasoning?"
"Explain the concept."
"Ask me questions that lead me to the solution."
```
- Avoid:
```
"Write the complete implementation."
A practical ratio
```
- A healthy balance for long-term growth is roughly:
- 70–80% thinking/coding yourself
- 20–30% AI assistance
